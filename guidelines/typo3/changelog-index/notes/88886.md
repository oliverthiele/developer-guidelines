# #88886 — Extbase persistence respects the language overlay type

**Antipattern:**

- A template guard such as `<f:if condition="{record.relation}">` as the fix. The
  error disappears, the translated page renders without the record, and nobody
  is told.
- Setting only the parent record to `sys_language_uid = -1`. Its file references
  and child records stay in language `0` and are still dropped.
- Writing translations or language values with SQL. `l10n_parent`,
  `l10n_source`, `l10n_state`, the file references and the reference index are
  not maintained; the frontend can look right while the backend does not.
- Expecting `-1` to act as a fallback until a translation exists. A translation
  of a `-1` record is never loaded.

**Correct:** decide per table what the data is — translated, `-1` including its
children, `0` with `OVERLAYS_MIXED`, or not language aware — and apply it through
the backend or DataHandler. See `guidelines/typo3/practices/record-languages.md`.
Nullable getters and template guards follow from that as defence, not as the fix.
Test at least one translated language.

**Why it was tempting:** the symptom is on one template line and goes away in a
minute, and the default language — where testing usually happens — never showed
a problem.
